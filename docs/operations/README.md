# CoopCheck 运营工作区

本目录保存 **可重复执行的运营 SOP、渠道规则、执行日志及复盘依据**。每次运营前先读本目录，执行后及时更新，避免在聊天记录里丢失关键决定。

## 当前 SOP（2026-10-25 V1.1）

**默认触发语**：“运营一下鸡舍项目”=**十模块必须逐一执行并交付本轮新增可验收成果（目标 10/10）**，不能仅巡检；“继续运营”=优先接续 LOG 未完结事项；“复盘一下”=按 GSC/GA4/付费转化判断渠道是否值得投入。

固定十模块：**邮件 → 外链与编辑合作 → Reddit → BackYardChickens → Pinterest → YouTube → GSC → GA4/转化 → SEO 内容 → 代码与线上**。这是**执行和验收清单**，不是只看一眼的巡检表；合规受阻可以保留成品和证据但不得记为完成，也不能为了凑数刷帖、乱发邮件；遇到邮件回复、线上异常、支付故障等 P0 事项优先处理。具体操作、历史法规证据约束、可量化标准与验收要求见 [SOP.md](SOP.md)。

**执行闭环**：先读 [SOP](SOP.md) + [LOG](LOG.md) → 10 模块每项主动推进真实新增交付 → 验证发布/发送/部署等证据 → 追加 LOG（✅完成/🟡部分/⛔阻塞/❌未完成）→ 按实际成果数报告，绝不把单纯查数据或仅写 Issue 算完成。以真实目标访客、工具使用、有效反链和付费收入衡量，不把“已发送/已提交/已发布”混作成功转化。

## 适用于今后各项目的统一约定

默认在**各项目自己的仓库**创建以下结构，不与业务代码混放：

```text
docs/operations/
├── README.md    # 入口、规则约定、状态和快捷链接
├── SOP.md       # 该项目具体运营步骤与渠道规则
└── LOG.md       # 每次执行事实、结果、链接和后续任务
```

- 新项目建立自己的 `docs/operations/`，不同项目的渠道与话术不直接照搬。
- 若项目已有运营目录，优先沿用，并在 README 中做导航，不强行建立重复目录。
- 修改运营策略应更新 SOP；每次实操都追加 LOG（时间、渠道、URL、动作、公开状态、可量化结果、待办）。
- 保存原始指标的**日期窗口**及来源，绝不将「发出请求」「提交待审核」「成功公开」「产生有效外链」混为一谈。
- 禁止在仓库中写入账号密码、2FA、会话 cookie、API 密钥、私人联系方式或未公开的敏感信息。
- 执行外部登录和身份验证时，由用户自行操作；运营可以自动准备内容、搜索、核对、合规发布并记录真实结果。
- 遵守平台规则：不灌水、不批量顶帖、不冒充真实养鸡经验、不凭空夸大法规的准确性或工具能力。
- **使用 cfbrower：默认只保留和复用唯一 1 个 tab。** 每次任务开始确认 tab 数；非必要不新建标签；旧无关标签能关则关，失败如实说明，绝不通过新标签绕过。
