# CoopCheck 运营 SOP

**版本：V1.2（2026-10-26） · 适用项目：CoopCheck · 站点：https://coopcheck.serunio.com/**

> 本文是“运营一下鸡舍项目 / 继续运营 / 运营复盘”的现行执行约束，替代 2026-10-13 旧版的仅四项例行流程。旧版已经确立的法规证据、账号安全和单标签页约束继续有效。每轮先阅读本文件与 LOG.md，完成后写入 LOG.md。遇到与历史记录冲突的执行优先级，以本文件为准；历史数据以当期可验证事实为准。

## 1. 唯一目标与衡量口径

北极星目标：**来自真实目标用户的有效工具使用和付费收入**，而不是操作数量、空泛曝光或凑外链。

指标层级：
1. **商业结果**：已核验订单、净收入（区分退款/测试订单）、有效的付费漏斗。
2. **有效使用**：真实独立访客、Quick Check / Planner / 计算器启动、生成、导出、结账点击、成功支付（严格区分事件次数与人数）。
3. **获客**：Google 自然点击、有效引荐访问、视频/Pin 带来的访问（排除运营者和测试流量，无法排除则注明）。
4. **增长前置信号**：GSC impressions、CTR、索引覆盖、可公开的社区回复、编辑采纳与真实反链。

“联系已发出 ≠ 对方已收到 ≠ 合作已接受 ≠ 链接已公开 ≠ 获得访问”；“索引请求已提交 ≠ Google 已收录”；“内容已发布 ≠ 带来真实用户”。无数据记 **未知/暂不可测**，不能写成零或成功。

## 2. 触发语与执行规则

- **“运营一下鸡舍项目”**：默认执行 **10 模块实操交付轮**，每个模块都要尝试完成独立、真实、可核验的本轮新增产出（见第 2A 节），不可以仅浏览、查数据、写建议就标记完成。
- **“继续运营”**：先接续 LOG.md 中的未完成、待回复、待审核和待验证任务，再执行本轮常规检查，不重新从零寻找机会。
- **“重点运营 [渠道]”**：集中推进指定渠道，同时检查重要邮件、线上故障和其他 P0 阻塞。
- **“复盘一下”**：以 GSC、GA4、站外渠道实际数据与转化为中心，比较上一观察窗口，提出加码/停止/修复决策。
- 一轮结束必须更新 LOG.md 并输出按模块核算的成果报告；**只巡检 / 待执行 / 受阻 / 仅草稿不得标成完成**，无法完成要附已做的替代动作、具体阻塞及下次可执行条件。
- 每轮目标数量是参考区间，不可为凑数牺牲内容质量、合规或目标相关性。

## 2A. 强制交付门槛（2026-10-25 用户新增约束；高于“巡检”条款）

**核心原则：运营 = 执行并交付，不是检查。** 每个模块必须产生一个与该模块直接相关的 **本轮新增动作/资产**，附能够回查的事实证据。统计、浏览旧帖子、打开 GSC/GA4、罗列候选网站、提出建议、创建空泛 Issue，**只能算准备工作，不能单独算完成**。一个动作不得在两个模块重复记功（除非确有分别可验收的独立交付物）。

- **完成（✅）**：达到下方对应的模块交付标准，包含唯一成果 URL/ID、动作时间、状态证据；可由用户或下轮复查。
- **部分完成（🟡）**：产生可用成品但因可核实的权限、登录、版规、审核、源数据缺失而无法完成外部提交/上线。例如成稿/可直接上传的视频、确认有用的官方原文调查及针对性的可提交稿件。列出成品保存位置和最后缺少什么，**不得算已发布或 10/10 完成**。
- **未完成（❌）**：只有浏览、数据、候选、一般性计划或空泛 Issue；或者没有证据。明确说明原因和已经试过哪些合理办法，继续追踪。
- **阻塞（⛔）**：如有安全限制、真实平台禁令或权限要求，标“阻塞”并保存合规替代成品；不以刷帖、编造经历、邮件群发、买链接、绕过封禁、编造法规、重复索引请求填补指标。阻塞不计✅。
- **目标**：**每轮 10/10 实操交付**；若客观不可实现，真实显示“✅N / 🟡M / ⛔K / ❌L”，不将计划、浏览量、待审核或草稿包装为已完成，也不承诺对方回复、Google 收录或订单等不可控结果。

### 执行流程（禁止提前收工）

1. **查**：在每个模块先调查本轮最新事实和上轮待办，排除已发布、已联系、已提交的重复动作。
2. **做**：执行该模块的首选动作；若不允许或缺条件，尝试同模块内其他合规高价值动作，不得轻易用“没有机会”结束。
3. **验**：取得发布时间、公开链接、发送 ID、GitHub commit、CI/部署/页面验证等**真实**证据；第三方采纳、索引、转化单独观察，不作为发帖/提交成功的替代。
4. **记**：即时写入 LOG 的十模块“新增产出 / 证据 / 状态 / 阻塞 / 下一步”，下轮先接续未完成的成品及外部回信。
5. **报**：先按 ✅/🟡/⛔/❌ 报 10 项交付情况，再列实际新发、新上线、站外引荐与可核验商业结果。**不能把 10 次巡检说成 10 个已执行任务。**

**上一轮追认（2026-10-25）**：当时主要做数据巡检、历史帖子回看和 Issue 创建，虽确有一封 CityHubGo 原线程跟进邮件发送，但**未达到 10 模块各有实操产出的目标**。应按本版本重新标注尚未完成模块，不宣称 SOP 全面执行成功。

## 3. 优先级和执行顺序

**开始前（强制）**：先读 SOP.md、README.md、LOG.md 最新记录，确认待办和账号/浏览器限制；检查最近执行过的动作，避免重复邮件、索引提交、发布或付费操作。

**P0 / 首先处理**：邮件回复与合作回访、线上可用性和支付异常、GSC/GA4 异常、已公开内容的审核/投诉/拦截。出现故障先定位，未发现故障则正常推进 P1。

**P1 / 主要增长**：高相关外链与媒体合作、Reddit、BackYardChickens、Pinterest、YouTube；用可复用的高质量内容争取真实目标访客。

**P2 / 持续积累**：关键词和页面内容、逐字段法规证据、SEO 技术问题、工具产品体验、代码优化。

**最后**：逐项核对 10 个模块是否真的有**本轮新增的实操交付物**，附链接/发送回执/提交记录/commit/上线证据；没有的明确标为“未完成”，不可用“已巡检”冒充完成，更新 LOG.md 并汇报。

### 各模块特别约束

**邮件与外链**
- 优先联系真实编辑、有投稿机制且受众匹配的网站；个性化说明对方读者为什么受益，不批量模板群发、不购买链接、不伪造身份/养鸡经历。
- 每个候选记录域名/栏目、相关度、投稿规则、可验证联系入口、联系人来源、联系日期、回复状态、公开 URL；未核实投递成功标为“送达未知”。
- 社区帖子中含 CoopCheck URL 且确认公开时，才记作“公开自有链接”；第三方政府引用不是 CoopCheck 反链。可索引反链需另行验证。

**Reddit 与 BYC**
- 对标版规并尊重“No AI content”、反广告及版主审核要求；不能以“内容基于事实”绕过 AI 内容限制。发现删除、警告、明显反感即停止对应推广并记录。
- 回复重事实、官方原文、适用条件；禁止刷量、复制黏贴、无关插链。不模拟客户证言或个人实际养鸡经历。
- BYC 待审核与邮箱验证状态先复查再新增回复，不重复发表等待审核的内容。

**Pinterest**
- 2026-10-20 曾出现 CoopCheck 官网链接被 Pinterest 拦截，域名验证成功不等于解封。**先验证当前限制是否解除**；未解除时按渠道规则申诉或发布无外链 Pin，不能使用短链/跳转规避限制；无外链不得记引荐流量。
- 用户希望图片无可见“AI”文字和水印；这不豁免平台要求的生成式内容披露。信息图须校验数字、城市及图片中陈述。
- **Pin 发布页空白先走第 5B 节浏览器减负流程**，明确区分“页面未渲染”“文件无法上传”“CoopCheck 落地链接被拦截”，三者不能混为一谈；后两者分别处理。

**YouTube**
- 检查公开视频真实 URL、公开可见性、封面、描述、置顶评论（如适用）及站点链接；没有上传凭据或发布确认时记阻塞。
- 不将视频发布、播放次数、官网点击、订单混写。优先复用已有 GitHub Actions 视频制作资产，避免重复手工制作。
- **上传本地视频、封面优先复用第 5A 节 GitHub 素材中转流程**；历史已成功通过 GitHub 中转完成 Shorts 和缩略图上传。禁止先反复尝试直接读取另一个运行环境的 `/mnt/data`；需要先将文件放到远程浏览器允许读取的目录并验证。

**GSC**
- 检查 Sitemap 与正式页面一致性；只对更新有实质内容、具备质量和索引资格的高优先 URL 视情况请求收录，保留上次提交日期及状态；不对同一 URL 无意义反复请求。
- 已发现未抓取、已抓取未收录等问题先排查内容质量、内部链接、重复页、规范化、robots/noindex 与渲染；报告有延迟，不能凭单日数据断言效果。
- 法规条件尚未核清的 needs_review 页面维持 noindex、不进入 Sitemap、不参与确定性合规判断；不为了覆盖量直接取消限制。

**GA4 与产品**
- 同时列出事件数、可能的独立用户数、数据时间窗口；检查既有 paid_report_offer_view、paid_report_planner_click、paid_report_checkout_blocked 等漏斗事件，不把 checkout_blocked 自动判定为支付网关故障。
- 任何付费/退款等真实交易操作、风险性账号设置变更，必须经用户确认；测试优先无扣款的功能路径。

**内容 / 法规 / 代码**
- 法规逐字段查官方当前有效法律或政府指南，重点为数量、公鸡、许可、退距及测量参照、地块与适用条件；source_recorded 只说明找到来源，**不等于结论已验证**。
- 保持政策证据主数据与生成文件一致，按现有仓库生成链和 CI 更新，避免手改生成产物；新增内容要对搜索需求和独特价值负责，不批量扩城市凑数量。
- 代码变更先测，再经过现有 CI / 部署流程，最后线上复核；遇到未完成 PR、发布条件或权限限制，不把本地分支当上线。

## 5A. GitHub 素材中转上传 SOP（YouTube / Pinterest；优先于重做素材）

**触发条件**：视频或图片已在生成环境产生，但 cfbrower 的 Playwright 远程 Chrome 无法直接读取本机 /mnt/data；例如实际出现 `File access denied: /mnt/data/... is outside allowed roots`。这是**两个隔离的文件系统**，不是 MP4 本身损坏。2026-10-26 查到远端允许目录为 `/var/lib/playwright-mcp/` 与 `/var/lib/playwright-mcp/.playwright-mcp/`，未来以新报错列出的 allowed roots 为准。

1. **先复用成品**：检查 LOG 中既有 MP4 / 竖图 / 封面 / 标题 / 配文和上次发布状态；核实文件真实存在、体积、分辨率/编码/时长，避免因浏览器问题重新生成内容。已发布的视频绝不重复发布。
2. **GitHub 桥接（首选）**：按已成功过的“素材 → GitHub 仓库、Release、Actions 可下载产物等经过授权的承载方式 → 可由远端访问的 HTTPS 下载位置”中转。先检索现有 Shorts 制作工作流及旧执行记录，不重新发明传输管道。**GitHub Actions artifact 通常需要身份验证，不等于公开直链**；确认访问控制。二进制 MP4 / JPG / PNG 应通过真正支持二进制上传的路径传递，**不要**把 UTF-8 文本更新接口当二进制上传器。只对允许公开的成品使用公开 URL，不将 Cookie、令牌、私有图像或未授权素材公开。
3. **把内容下载到浏览器端**：用远程环境实际支持的下载/文件传输操作将文件保存至 Playwright 当前允许的目录（上述目录仅为本次实测示例），不能把“网页能打开 GitHub URL”当成“上传控件能读取文件”。远程与生成容器路径不同；必要时以允许的下载链先取得可读取本地副本。验证 HTTP 状态、类型/体积（适用时比较 SHA-256）和远端文件确实存在，不使用 HTML 预览页冒充视频文件。
4. **完成平台上传**：在唯一浏览器 tab 内打开 Studio 或 Pin 创建页，使用浏览器支持的文件选择器/拖放操作引用**远端允许目录内的真实绝对路径**；完成标题、说明、图片/封面、版权/生成内容披露和公开权限，提交并获得成功回执。YouTube 上传网页不能直接粘贴 MP4 URL 来代替本地文件选择；**桥接 URL 是传输介质，不是发布视频 URL**。
5. **验收+清理**：核对新 Shorts / Pin 公开 permalink，平台公开视频/图片状态，是否链接正确；清理不再需要的中转副本/临时公开素材（勿误删其他正在使用的工作流、共享素材）。未取得公开 URL 时只计“成品/传输成功/待审核”的对应真实阶段，仍按 SOP 第 2A 节记 🟡/⛔，不得记 ✅。
6. **桥接失败的分支**：如果当前工具没有安全可靠的 GitHub 二进制上传能力、公开文件访问被拒绝或浏览器无法接收/下载文件，记录卡在哪一跳以及具体权限报错，尝试现有合法授权的 Actions 工作流或服务器侧文件传输；不要反复对错误的 `/mnt/data` 路径调用浏览器上传，也不要声称只有“手动上传”可选。

## 5B. 远程浏览器减负与空白页恢复 SOP（2C2G；先执行再排障）

**触发条件**：Pinterest 创建页空白、YouTube Studio 上传弹窗卡住、Playwright 操作超时、`UNAVAILABLE`、`Tab not found`，或 Chrome 进程/内存异常。

1. **先数标签，先清理**：执行 `browser_tabs(list)`，记录当前 tab、URL、是否有正在上传的任务/未保存内容。保留 **唯一 1 个正在操作的标签**，额外标签原则上逐一关闭；有未提交内容时先保存/避免关闭。用户明确要求减少多余标签页带来的内存消耗。
2. **关闭必须再次核验**：每次 close 后再次 `browser_tabs(list)`，索引发生变化要重新取索引，建议由高索引向低索引关闭。若 `Tab N not found` 或连接失败，**不是已关闭的证据**；重新 list，重试一次有效索引或检查远程服务健康，不得写“已清理 1 tab”。
3. **复用单 tab、降低负载**：顺序完成 GSC、GA4、Reddit、BYC、Pinterest、YouTube，不同时打开多个重型网站/多个 Chrome 实例；必要时关闭失效空白页后在保留 tab 导航。再次观察内存、CPU、进程/线程与 pids 限额；仅据实际测量决定是否需要重启 Chrome/CDP/Playwright 服务，不把 2C2G 推测直接当根因。
4. **验证页面是否真正渲染**：导航后查 `document.readyState`、`document.body.innerText`、关键上传控件、页面日志与失败的网络请求。若 HTTP/HTML 已加载但 React 主体停在 `<template>` 且 body 无文字、无上传控件，判断为“前端未完成渲染”，**不能**声称账号被封或文件损坏；先单 tab 重新导航、恢复浏览器服务健康，再对照其他页面。
5. **稳定交互与分支修复**：如果按钮位于视口外先滚动/适当调整窗口尺寸后再点击；如果 YouTube Studio 出现“糟糕，出了点问题，重试”，查真实请求和会话后重试，勿无限循环。若上传控件可见但文件被拒绝，转第 **5A 节 GitHub 中转**；若 Pinterest 创建页根本未渲染，优先恢复浏览器，不用 GitHub 中转伪装解决前端故障；若是 Pinterest 目的域名被拦，走正规申诉，禁止跳转链接绕禁令。
6. **收尾**：最终再 list，记“剩余 tab 数 + 当前 URL + 是否仍有无关 tab + 清理成功/失败错误”。若无法安全关闭，明确标阻塞并记入 LOG 供下次系统层排查。页面能打开 ≠ 上传成功，上传成功 ≠ 发布公开。

## 5. 通用执行守则

1. **浏览器资源（强制排障顺序）**：cfbrower 开始、切换重型站点前、异常时、结束时均列出 tab；始终以 **1 个 tab** 为目标，复用当前标签顺序访问平台；多余 tab 先核对是否有未保存表单/上传，再关闭，清理后再次列出核验；不得只凭调用 close 就声称成功。异常按第 5B 节执行，2C2G 服务器优先减少标签页和进程/内存负荷。
2. **账号安全**：不在仓库保存密码、2FA、Cookie、API 密钥、非公开联系方式；涉及身份验证让用户完成。无法实际完成的操作不可谎称成功。
3. **渠道安全**：不群发垃圾信息、不恶意 SEO、不伪造官方条款、不绕过验证码、审核、封禁、域名拦截、社区规则；账号与声誉优先于配额。
4. **可追溯性**：关键数字必须记录来源、数据窗口、时区及提取时刻；公开 URL 需核查；必要时加合法 UTM，但不得违反平台链接规则或将 UTM 当作新的独立页面。
5. **止损**：明确禁用/警告的渠道暂缓发布并查明原因；同质内容效果持续差或风险高时提出减少投入，不因“固定动作”继续无效运营。
6. **权限边界**：常规获授权的内容运营、非敏感沟通和仓库可控修复可推进；购买服务、产生收费、删除重要数据、危险账号变更或未经确认的身份验证不自行执行。
