# CoopCheck 运营 SOP

**版本：V1.0（2026-10-25） · 适用项目：CoopCheck · 站点：https://coopcheck.serunio.com/**

> 本文是“运营一下鸡舍项目 / 继续运营 / 运营复盘”的现行执行约束，替代 2026-10-13 旧版的仅四项例行流程。旧版已经确立的法规证据、账号安全和单标签页约束继续有效。每轮先阅读本文件与 LOG.md，完成后写入 LOG.md。遇到与历史记录冲突的执行优先级，以本文件为准；历史数据以当期可验证事实为准。

## 1. 唯一目标与衡量口径

北极星目标：**来自真实目标用户的有效工具使用和付费收入**，而不是操作数量、空泛曝光或凑外链。

指标层级：
1. **商业结果**：已核验订单、净收入（区分退款/测试订单）、有效的付费漏斗。
2. **有效使用**：真实独立访客、Quick Check / Planner / 计算器启动、生成、导出、结账点击、成功支付（严格区分事件次数与人数）。
3. **获客**：Google 自然点击、有效引荐访问、视频/Pin 带来的访问（排除运营者和测试流量，无法排除则注明）。
4. **增长前置信号**：GSC impressions、CTR、索引覆盖、可公开的社区回复、编辑采纳与真实反链。

“联系已发出 ≠ 对方已收到 ≠ 合作已接受 ≠ 链接已公开 ≠ 获得访问”；“索引请求已提交 ≠ Google 已收录”；“内容已发布 ≠ 带来真实用户”。无数据记 **未知/暂不可测**，不能写成零或成功。

## 2. 触发语与执行规则

- **“运营一下鸡舍项目”**：按 10 模块完整巡检并推进可执行的高价值任务；不代表每次都必须在每个渠道发帖。
- **“继续运营”**：先接续 LOG.md 中的未完成、待回复、待审核和待验证任务，再执行本轮常规检查，不重新从零寻找机会。
- **“重点运营 [渠道]”**：集中推进指定渠道，同时检查重要邮件、线上故障和其他 P0 阻塞。
- **“复盘一下”**：以 GSC、GA4、站外渠道实际数据与转化为中心，比较上一观察窗口，提出加码/停止/修复决策。
- 一轮结束必须更新 LOG.md 并输出执行报告；无法操作的模块标记 **阻塞/跳过 + 原因 + 下次动作**，不得假装已执行。
- 每轮目标数量是参考区间，不可为凑数牺牲内容质量、合规或目标相关性。

## 3. 优先级和执行顺序

**开始前（强制）**：先读 SOP.md、README.md、LOG.md 最新记录，确认待办和账号/浏览器限制；检查最近执行过的动作，避免重复邮件、索引提交、发布或付费操作。

**P0 / 首先处理**：邮件回复与合作回访、线上可用性和支付异常、GSC/GA4 异常、已公开内容的审核/投诉/拦截。出现故障先定位，未发现故障则正常推进 P1。

**P1 / 主要增长**：高相关外链与媒体合作、Reddit、BackYardChickens、Pinterest、YouTube；用可复用的高质量内容争取真实目标访客。

**P2 / 持续积累**：关键词和页面内容、逐字段法规证据、SEO 技术问题、工具产品体验、代码优化。

**最后**：核对发布/提交的实际状态，记录链接和证据，写 LOG.md，向用户报告本轮收获以及下轮 1–3 个最高优先级任务。

## 4. 固定 10 个运营模块

| # | 模块 | 每轮必查 / 可推进事项 | 参考产出（不是强制配额） |
|---|---|---|---|
| 1 | **邮件** | 检查合作回复、支持邮箱、退信、审核与 Pinterest 等平台申诉进展；跟进先前联系，不重复群发 | 处理全部重要邮件；记录回复与下一步 |
| 2 | **外链/编辑合作** | 搜索鸡舍、园艺、DIY、家禽和本地法规相关资源；核实投稿入口及版规；以可引用的城市法规和真实工具为基础个性化联络 | 评估 5–10 个目标，合适时联系 3–5 个 |
| 3 | **Reddit** | 查近期相关真实问题与历史回复；先看社区禁令和帖子上下文，只提供有依据、有帮助的回答；外链仅在允许且相关时附上并披露关系 | 2–5 次有意义互动（不足可少做或不做） |
| 4 | **BackYardChickens** | 关注 Local Chicken Laws & Ordinances 及其他匹配主题；优先核验城市官方原文，跟进先前帖子审核 | 1–3 次有价值互动（含历史跟进） |
| 5 | **Pinterest** | 研究 Pin 表现、落地页与站点域名拦截状态；生产实用原创版式/图解，核查引文与链接，发布后复查公开状态 | 适合时发布 2–3 张原创 Pin |
| 6 | **YouTube** | 检查 Shorts 数据、已有视频评论与链接；用仓库已有录屏/制作流程做尺寸、法规、图纸演示；核验内容、配音、封面、字幕 | 争取 1 条可公开且合规的 Shorts |
| 7 | **GSC / 收录** | 对比 7/28 天 clicks、impressions、CTR、position 与查询/页面；检查索引原因、Sitemap、Canonical、noindex、页面更新日期和重点 URL | 形成优先页面/异常清单，按实际需要处理 |
| 8 | **GA4 / 转化** | 核对有效访客来源与事件漏斗，特别是使用 Planner/导出/付费；将测试流量与真实用户分开；联动渠道来源 | 输出本轮获客和转化事实（注明观察窗口） |
| 9 | **SEO / 内容** | 研究搜索需求和长尾词，维护工具指南/城市页内容/FAQ/结构化数据；核查法规证据与已有页面重复度 | 推进 1 个高价值且证据充分的内容任务 |
| 10 | **代码 / 线上** | 检查支付与工具链路、移动端、性能、可抓取性、错误和 GitHub 待办；有问题才修复，走测试/CI/部署/线上核验 | 最高优先级修复和可验证结果 |

### 各模块特别约束

**邮件与外链**
- 优先联系真实编辑、有投稿机制且受众匹配的网站；个性化说明对方读者为什么受益，不批量模板群发、不购买链接、不伪造身份/养鸡经历。
- 每个候选记录域名/栏目、相关度、投稿规则、可验证联系入口、联系人来源、联系日期、回复状态、公开 URL；未核实投递成功标为“送达未知”。
- 社区帖子中含 CoopCheck URL 且确认公开时，才记作“公开自有链接”；第三方政府引用不是 CoopCheck 反链。可索引反链需另行验证。

**Reddit 与 BYC**
- 对标版规并尊重“No AI content”、反广告及版主审核要求；不能以“内容基于事实”绕过 AI 内容限制。发现删除、警告、明显反感即停止对应推广并记录。
- 回复重事实、官方原文、适用条件；禁止刷量、复制黏贴、无关插链。不模拟客户证言或个人实际养鸡经历。
- BYC 待审核与邮箱验证状态先复查再新增回复，不重复发表等待审核的内容。

**Pinterest**
- 2026-10-20 曾出现 CoopCheck 官网链接被 Pinterest 拦截，域名验证成功不等于解封。**先验证当前限制是否解除**；未解除时按渠道规则申诉或发布无外链 Pin，不能使用短链/跳转规避限制；无外链不得记引荐流量。
- 用户希望图片无可见“AI”文字和水印；这不豁免平台要求的生成式内容披露。信息图须校验数字、城市及图片中陈述。

**YouTube**
- 检查公开视频真实 URL、公开可见性、封面、描述、置顶评论（如适用）及站点链接；没有上传凭据或发布确认时记阻塞。
- 不将视频发布、播放次数、官网点击、订单混写。优先复用已有 GitHub Actions 视频制作资产，避免重复手工制作。

**GSC**
- 检查 Sitemap 与正式页面一致性；只对更新有实质内容、具备质量和索引资格的高优先 URL 视情况请求收录，保留上次提交日期及状态；不对同一 URL 无意义反复请求。
- 已发现未抓取、已抓取未收录等问题先排查内容质量、内部链接、重复页、规范化、robots/noindex 与渲染；报告有延迟，不能凭单日数据断言效果。
- 法规条件尚未核清的 needs_review 页面维持 noindex、不进入 Sitemap、不参与确定性合规判断；不为了覆盖量直接取消限制。

**GA4 与产品**
- 同时列出事件数、可能的独立用户数、数据时间窗口；检查既有 paid_report_offer_view、paid_report_planner_click、paid_report_checkout_blocked 等漏斗事件，不把 checkout_blocked 自动判定为支付网关故障。
- 任何付费/退款等真实交易操作、风险性账号设置变更，必须经用户确认；测试优先无扣款的功能路径。

**内容 / 法规 / 代码**
- 法规逐字段查官方当前有效法律或政府指南，重点为数量、公鸡、许可、退距及测量参照、地块与适用条件；source_recorded 只说明找到来源，**不等于结论已验证**。
- 保持政策证据主数据与生成文件一致，按现有仓库生成链和 CI 更新，避免手改生成产物；新增内容要对搜索需求和独特价值负责，不批量扩城市凑数量。
- 代码变更先测，再经过现有 CI / 部署流程，最后线上复核；遇到未完成 PR、发布条件或权限限制，不把本地分支当上线。

## 5. 通用执行守则

1. **浏览器资源**：cfbrower 开始和结束均检查标签页；默认复用 **唯一 1 个 tab**，如不可避免才临时使用第 2 个，并说明原因和清理结果。禁止留下多个高负载网页，避免 2C2G 服务器过载。
2. **账号安全**：不在仓库保存密码、2FA、Cookie、API 密钥、非公开联系方式；涉及身份验证让用户完成。无法实际完成的操作不可谎称成功。
3. **渠道安全**：不群发垃圾信息、不恶意 SEO、不伪造官方条款、不绕过验证码、审核、封禁、域名拦截、社区规则；账号与声誉优先于配额。
4. **可追溯性**：关键数字必须记录来源、数据窗口、时区及提取时刻；公开 URL 需核查；必要时加合法 UTM，但不得违反平台链接规则或将 UTM 当作新的独立页面。
5. **止损**：明确禁用/警告的渠道暂缓发布并查明原因；同质内容效果持续差或风险高时提出减少投入，不因“固定动作”继续无效运营。
6. **权限边界**：常规获授权的内容运营、非敏感沟通和仓库可控修复可推进；购买服务、产生收费、删除重要数据、危险账号变更或未经确认的身份验证不自行执行。

## 6. 本轮执行记录与验收

每次运营必须在 docs/operations/LOG.md 顶部追加真实记录：

- 日期与时区、执行目标、读取的上一轮待办。
- **十模块检查表**：模块、执行/跳过/阻塞、事实及结果、URL/证据、下次动作；检查不等于发布。
- 邮件：联系人/渠道（必要时脱敏）、发出/退信/回复/待跟进；合作：候选/已投递/被接纳/链接公开/真实引荐分列。
- 社媒：内容标题、平台、公开 URL、发布时间及状态（草稿/已提交/待审核/公开/删除）。
- GSC：7/28 天观察窗口、点击、曝光、主要变化、索引与 Sitemap 最新核查时间；GA4：真实引荐、关键事件与付费链路，标注可能的自测污染。
- 代码：分支/PR/提交 SHA、测试/CI、是否部署以及线上验证结果；未上线不能填已修复线上。
- 数据支持的结论：本轮实际新增 **有效外链、真实访问、工具使用、核验订单和收入**（未知则写未知），哪些动作值得加码/暂停，以及下一轮最重要的 1–3 项。

对用户的最终报告保持简洁：**本轮完成的动作 + 对应链接证据；数据变化；未完成/阻塞；下轮 1–3 件最重要的事**。不能只给计划、不落地，也不能编造执行结果。

## 7. 复盘节奏

- 每轮：十模块巡检与执行记录。
- 每 7 天：比较渠道有效互动、公开链接、GSC/GA4、转化漏斗、站点稳定性，决定下一周资源投入。
- 每 28 天：按搜索主题与渠道对比有效流量、真实工具使用和付费结果，停止低回报重复动作；如 SOP 有策略变化则同步更新 README 和本文件。

## 附录 A：法规证据等级的既有专项规则（历史适用范围）

以下是 2026-10-13 的专项决议，历史基线数量仅用于追溯，**不是当前实时进度**；后续以仓库当前数据和最新专项文档为准。

### 2026-10-13 专项： 2026-10-13 法规证据等级补充（仅剩余45项）

原先对所有字段都要求当前正式法条或明确官方指南。应用户要求，**仅对12待审城市里的45个原`unverified`条目**允许降低为「市法典/市政府文档入口已找到」并记录为 `source_recorded`。严格区分：

- `primary_clause_checked`: 真实现行法条或行政指南明确支持该字段下写明的**有限结论**；必须记录条款、适用条件、官网链接及审查日期。
- `source_recorded`: 有可追溯的官方主题来源、法典检索入口、已采纳修订目录或州法条款，但**未证实该字段所需的当前适用结论**。新登记的45项必须写 `verifiedClaim:false`、`evidenceLevel`、`url`、`checkedAt` 及具体缺口。
- 不能把法典入口、普通建筑许可门槛、旧论坛内容、草案、卫生防鼠建议、独栋住宅州法保护看成一座城市全部家庭均可养鸡。
- **不能因为从 unverified 升级到 source_recorded 就发布可索引法规页**、开启自动合法性检查、显示确定的数量/退距、宣称无须许可或满足付款需求。12个待审城市仍 `needs_review`、`noindex`、manual。
- 口径上原329项已严格核验 + 原26项部分来源不变。新增45个有来源记录后，**合计71项依旧缺乏法规结论**，不可宣传「400/400已验证」。
- 所有逐字段可追溯参考见 `PENDING_45_EVIDENCE_TIER_2026-10-13.md`；若后续能直接核条款再升级，不得因为入口存在自动升级。
